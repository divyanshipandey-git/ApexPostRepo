# ADR-0009: Issue money orders inside the paid counter transaction

- **Status:** Accepted
- **Context:** A high-value money order and its successful identity verification must be traceable to the same paid counter transaction. Standalone money-order persistence cannot establish that business relationship or keep the order out of an unrelated sale.
- **Decision:** The counter-sale Application workflow creates the money order using configured fee and threshold settings, associates it with the generated transaction ID and authenticated branch, and adds the amount plus fee as a tax-exempt service line. Above the threshold, the workflow requires a successful identity-verification record using only a strict masked document identifier (`XXXX` plus four visible characters). The JSON repository writes the linked order before the transaction and exposes delete for compensation if a later write fails. The MVC form displays the fee and threshold, accepts no full document number, and follows PRG after success.
- **Consequences:** The transaction receipt and repository data prove the order's branch and transaction association. Unit and WebApplicationFactory tests cover successful high-value issuance, missing verification, unsafe document-number input, and compensating removal when transaction persistence fails. This remains a multi-file JSON workflow: compensation handles ordinary write failures but cannot guarantee crash-atomicity or coordinate multiple processes. The checkbox records staff attestation of an in-person check; it is not an external identity-provider integration.
